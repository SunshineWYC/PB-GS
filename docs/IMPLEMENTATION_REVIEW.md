# 实现复盘：从一个项目提炼到可复制流程

## 参考项目是怎样完成的

BlockGaussian 从已有 GitHub 仓库的 `project-page` 分支独立克隆到本地。它原先是 Bulma / Academic Project Page Template 风格的静态网页，包含视频轮播、图片比较和动态比较。后续集中改写 HTML、CSS 和 JavaScript；当前页面运行不依赖前端构建或外部字体，旧框架资源虽可能仍在历史仓库里，但不是新模板的依赖。

工作首先对照新版论文与旧网页：确认摘要、方法细节、实验表、街景泛化、效率证据和方法边界。重要论点逐个绑定论文表格或图，不把网页写成论文逐页搬运。页面最后按“首屏价值 → 摘要 → 方法 → 渲染质量 → 效率 → 演示 → 局限 → 引用”组织。这个顺序服务于该论文；下一篇论文应重新决定。

素材采用分层处理：原 PDF 和 charts 保留在 materials/；论文截图导出清晰 PNG，渲染图使用 WebP，视频沿用经过确认的展示文件。存在来源冲突时记录处理决定，数值计算只使用已确认口径。最终由用户决定表格直接采用截图，减少重复制表造成的错误。

排版经过逐模块统一：正文、图注、标题和控件各有稳定字号，摘要和局限与其他章节同宽；清理编辑过程说明、无意义换行、重复铺图和占位链接。桌面与手机分别检查，宽图可查看原尺寸，宽表局部滚动。

交互将自动轮播改成具名场景切换；图片比较保留直接拖动，并修复缩放和混合键鼠操作导致的错位；视频比较按容器维护状态，隐藏即暂停，不依赖全局位置、重复 ID 或克隆节点。引用复制直接读取当前显示的 BibTeX，避免两份文本不同步。

发布前核对数据、文字、资源路径大小写、公开范围、链接、交互和响应式布局；然后明确提交范围，推送现有发布分支。遇到认证阻碍时区分“连接能读”和“实际能写”。最后确认指定提交的 Pages 工作流成功，并核对正式 URL、资源和引用，而不是把推送完成当作上线完成。

## 模板保留什么，改变什么

| 保留的经验 | 为从零建站做的调整 |
| --- | --- |
| 证据驱动的内容组织 | 先材料清点和内容方案，不依赖旧网页 |
| 静态 HTML/CSS/JS | 提供独立骨架和可删除组件，不复制旧 Git 历史 |
| 统一字体和容器 | 用公共变量管理，不为各章节随意定字号 |
| 原图导出与数据溯源 | 通用导图脚本，坐标和来源记录留在本地 |
| 直接图片比较、具名场景 | 图片比较采用独立 CSS 裁剪实现；无 DICS 依赖 |
| 按容器管理动态比较 | 可选模块，默认手动播放；按需启用自动播放 |
| 私有材料不提交 | 额外隔离 site/，本地服务与部署都只暴露此目录 |
| GitHub Pages | 新独立仓库默认 main + 明确的 Actions 工作流 |
| 发布前检查 | 可执行的草稿/发布检查，阻止示例占位内容上线 |

## 不应机械继承的内容

不要继承上一项目的论文题目、作者、单位、仓库、arXiv 编号、实验图、GPU 型号、加速倍数、场景名、分块数、BibTeX、录用标记和来源冲突决定。不要默认每篇论文都有三模块方法、效率贡献或街景结果。

“顶会项目页风格”在这里指清晰的研究定位、可信证据、克制设计和便于阅读的演示，不是某个会议强制的网页格式认证。
