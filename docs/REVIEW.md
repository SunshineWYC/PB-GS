# 发布前检查清单

静态脚本只查一部分技术错误。Codex 必须把实际操作和结论写入 notes/review.md；检查失败就处理明确问题，不把“脚本通过”写成“数据科学性已自动验证”。

- 身份：页面、浏览器标题、分享标题、作者和引用一致；单位/主页/公开链接有依据；无未经确认的会议、期刊、年份或接收标签。
- 全文：逐段读正文、图注、展开区、所有标签面板、图片 alt 和动态状态；清除占位词、manuscript 修订说明、无意义换行和编辑用小字。图中的文字也要检查。
- 科研：每个首页数字有来源；计算重算；方向、单位、硬件、数据集、比较对象明确；对各模块的收益不夸大归因；局限与实际结果一致。
- 素材：源稿未改；PDF/charts 不随提交泄露；网页图完整、清晰；没有重复铺图、误用图号、未展示内容残留或无法解释的截图。
- 布局：1440、768、390px 及必要的 320px；同级文字统一、正文不太小；摘要/局限与其他模块同宽；无页面级横向溢出、遮挡和重叠。
- 交互：所有场景、键盘、鼠标和触摸；图片原尺寸/关闭；逐段视频播放暂停；隐藏视频及画布停止；比较画面在缩放、换场景后仍对齐；复制内容与显示完全一致。
- 技术：控制台及请求无异常；路径大小写一致；相对资源在 `/仓库名/` 子路径下有效；禁用 JavaScript 后可读；慢加载/失败有合理状态。
- 公开范围：git ls-files、git diff --cached 和 site/ 清单同时检查。Git 忽略规则对已跟踪文件不生效；若材料曾被提交，先处理历史暴露风险，不能只加 .gitignore 就声称解决。
- 发布：release.json 设置真实信息；清除全部示例素材和占位标记；`python scripts/check_site.py --release` 为零错误。GitHub Pages 上传目录必须是 site/。

模板 `--release` 会因空信息失败，这是预期行为。它不检查网络外链、图像 OCR、数值计算、视频编码和视觉美观，这些项目需另做实际验证并如实说明未测范围。

线上验收需取得三类证据：远端指定提交、对应部署成功、正式 URL 展示正确。不要仅检查一个随机成功的历史 workflow。缓存延迟时等待或强制刷新后再判断。
