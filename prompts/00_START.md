# 从材料到完整本地网页

直接复制以下提示词。项目身份和材料路径填写在 PROJECT_BRIEF.md，无需在提示词中重复。

请基于当前 project_page 目录，为目标论文制作完整的英文项目页。

先读取 AGENTS.md、README.md、PROJECT_BRIEF.md、docs/IMPLEMENTATION_REVIEW.md 和 docs/WORKFLOW.md，列出并阅读 materials/ 的实际材料。当前项目从这个独立模板开始，没有现成 GitHub 仓库或旧网页；不要克隆参考项目，也不要继承其作者、论文、数据、网址、Git 历史或远端。

按连续流程完成：

1. 确认目标论文版本、可公开范围、作者/链接/引用；记录材料清单和缺口。
2. 对照论文与 charts，筛选新增重点、关键证据和局限，建立 source-map 与冲突记录。
3. 设计一句话定位、贡献要点和“问题→方法→证据→范围”的叙事；把可复核方案写入 notes/content-plan.md 后继续实现，不为常规排版选择反复等待确认。
4. 导出实际展示素材，保留原材料；登记 public asset manifest。不要用虚构数字、模板示意图或其他论文结果填空。
5. 在 site/ 完成网页、内容、排版和交互。按论文决定章节，删除没有材料支持的模块。遵循 docs/DESIGN.md；方法图和 Teaser 默认直接插图；表格可直接使用清晰原表截图；具名场景切换，不自动轮播。
6. 全文检查，统一标题/正文/图注层级和内容宽度，检查桌面、平板、390px 手机；检查全部场景、比较、视频、高清图和引用复制，修复明确问题。
7. 保存 notes/review.md，提供本地预览、变更摘要、实际检查结果和剩余必要问题。

本轮授权材料读取、文件制作、独立目录内的本地 Git 初始化和本地预览；不创建远端仓库、不提交、不推送或部署。若当前目录仍在其他仓库内部，先说明复制位置问题，不向父仓库写入 Git 历史。缺失信息只在影响科学结论、公开范围或必需动作时询问，其他独立工作继续。
